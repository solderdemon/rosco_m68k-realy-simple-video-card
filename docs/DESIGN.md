# Design Notes: SolderDemon m68k Really Simple Video (r1)

How the card works and why it is built this way. The schematic and PCB are generated by
`tools/build_card.py`; the logic — and both CPLD pinouts — live in `code/firmware/cpld/rsv_u1.pld` and
`code/firmware/cpld/rsv_u2.pld`. Reference designators match the r1 schematic.

---

## 1. Block Diagram

 J1 bus ──A17..A8───►│                                  ▼                      │   │

Five ICs: two ATF1502AS, one AS6C1008, one 74HCT245, one 74HC166, plus the oscillator
and Q1, the video output transistor.

---

## 2. The split, and why it works

An ATF1502AS-10JU44 has **32 macrocells**. The 44-lead package has 32 I/O pins and 4 dedicated
inputs; four of the I/O double as JTAG and must stay reserved to reprogram the part in place. That
leaves **28 I/O + 4 inputs = 32 usable signals** per device.

An address multiplexer is 16 inputs and 16 outputs — 32 pins, the whole chip, before any logic.
One device cannot hold it, and it is *not* fixed by simply adding a second one: if the counters stay in chip A and the multiplexer moves to chip B, then all 16
counter bits have to cross between them, and both chips run out of pins.

The fix is to **split the counters along with the multiplexer halves**:

| | Holds | Pins | Macrocells |
|:---|:---|:---:|:---:|
| **U1** | pixel phase PH0–PH2, byte counter B0–B6, HBLANK, /HSYNC, /LOAD, bus decode, /DTACK, /SRAM_WE, /BUF_OE, "video on", the status read, **MA0–MA6** | 32/32 | 30/32 |
| **U2** | line counter L0–L9, VBLANK, /VSYNC, the page register, **MA7–MA16** | 30/32 | 30/32 |

MA0–MA6 comes from B, which lives in U1; MA7–MA15 comes from L, which lives in U2. No counter bit
crosses. Only three wires do:

| Wire | Direction | What it carries |
|:---|:---|:---|
| `SEL_N` | U1 → U2 | 0 = the CPU owns the SRAM address, so both halves switch together |
| `LEND` | U1 → U2 | high for the last clock of byte time 94; U2 steps L on the edge that ends it |
| `VBLANK` | U2 → U1 | for `BLANK` and for the status bit |

`LEND` is a register in U1, loaded one clock ahead (`PH == 6 & B == 94`), so it is glitch-free and
U2 has a full 25 MHz period of setup on it.

### Why the counters are written with XOR

A 10-bit binary counter written the GAL way — "hold unless every lower bit is set" — needs ten
product terms on its top bit. An ATF1502AS macrocell has five. So every counter bit here is

```
L8.D = (L8 $ (LEND & L7 & L6 & L5 & L4 & L3 & L2 & L1 & L0)) & !LCLR;
```

which is two product terms whatever the width, and maps onto the macrocell's own XOR gate.

## 3. Video Timing

| Parameter | Value |
|:---|:---|
| Oscillator | X1, 25.000 MHz, into both CPLDs' GCLK1 (through R7) and the 74HC166 shift clock (through R8) |
| Byte time | 8 clocks = 320 ns; one byte is eight pixels |
| Line | 100 byte times = 800 clocks, 31.250 kHz |
| Frame | 525 lines, 59.52 Hz |
| Visible | pixels 0-639 on lines 0-479 |
| Front porch / HSYNC / back porch | 16 / 96 / 48 clocks |
| VSYNC | lines 490-491, active low |

### Why 25.000 MHz and not 25.175

The VESA 640 × 480 @ 60 Hz table calls for a 25.175 MHz dot clock, which gives 31.469 kHz and
59.94 Hz. This card uses a plain **25.000 MHz** can instead, because that is the oscillator
everybody actually stocks — it is the Ethernet PHY clock, so it is in every parts drawer, while
25.175 MHz is a special order.

Nothing in the logic changes: still 800 clocks per line and 525 lines per frame, still the same
16/96/48 porches counted in clocks. Only the rates move, by **−0.70 %**:

| | 25.175 MHz (VESA) | 25.000 MHz (this card) |
|:---|:---|:---|
| Pixel clock period | 39.72 ns | 40.00 ns |
| Line | 31.778 µs, 31.469 kHz | 32.000 µs, 31.250 kHz |
| Frame | 59.94 Hz | 59.52 Hz |
| HSYNC width | 3.813 µs | 3.840 µs |

0.7 % is far inside what any multisync monitor or LCD scaler accepts — 25.000 MHz is the most
common VGA dot clock in the FPGA world for exactly this reason. Both rates land in the same
"640 × 480 @ 60 Hz" bucket when a monitor classifies the mode. If you do have a 25.175 MHz can,
fit it instead and the card becomes exactly VESA; nothing else needs changing.

Everything is clocked by CLK25; `BEND = PH2·PH1·PH0`
steps the byte counter and `LEND` steps the line counter, at the end of the HSYNC pulse and so
inside horizontal blanking — L is stable across the whole visible part of a line.

### The one-byte pipeline

The 74HC166 is loaded with byte *n* at the end of byte time *n* and shows it during byte time
*n + 1*. Rather than correct for that with an offset, `/HSYNC` and `HBLANK` are registers decoded
from the byte before the one they describe, so the register itself supplies the delay:

| Signal | Decode | Effect on the screen |
|:---|:---|:---|
| `HBLANK` | B in 79..98 | high for byte times 80..99, so the last load of a line is byte 79 |
| `/HSYNC` | B in 82..93 | low for byte times 83..94 = clocks 664..759 |

Bytes 0..79 are loaded during byte times 0..79 and shown during byte times 1..80 — clocks 8..647.
HSYNC at 664..759 leaves a 16-clock front porch and a 48-clock back porch (40 at the end of the
line plus the 8 at the start of the next). Exactly VESA.

### Blanking

`BLANK = HBLANK + VBLANK + /VIDEOON`, and it works by suppressing the load rather than by
disabling an output: with `/LOAD` held high the 166 keeps shifting, and its serial input is tied
to ground, so zeros walk in and the picture goes black within one byte. Nothing has to be
tri-stated, and there is no race between releasing a reset and the first load of a line.

### Counter wrap

B wraps at 99 = 1100011, the only reachable state with `B6·B5·B1·B0`; L at 524 = 1000001100, the
only reachable state with `L9·L3·L2`. States above the modulus cannot occur in normal operation
and walk into a wrap state within a few steps, so both counters recover from any power-up value —
the simulation checks all 128 and all 1024 of them.

## 4. Pixel Timing Budget

One byte has to come out of the SRAM in one byte time, 320 ns:

| Stage | Max, ns |
|:---|:---:|
| ATF1502AS-10, clock → B → MA0..MA6 (registered value out through a combinational macrocell) | ~12 |
| AS6C1008-55, address → data | 55 |
| 74HC166, setup | ~4 |
| **Total** | **~71 of 320** |

MA7..MA16 comes from L, which only
changes at line boundaries, so it is not on this path at all.

The one part that sees 25.000 MHz outside a CPLD is the 74HC166 shift clock. Nexperia specify
fmax = 40 MHz at 4.5 V over the full temperature range for that part, so there is 60 % of margin.
(Not every vendor's HC166 is rated the same; check the datasheet of what you buy.)

### Why the 166 is discrete

Because neither CPLD has eight spare pins for MD0–MD7: U1 is at 32/32 and U2 at 30/32.
The video drive does not constrain it either — Q1 takes the current (§7) — so it is a plain
74HC166.

## 5. Memory and Addressing

SRAM byte `n = page << 16 | y << 7 | x >> 3`:

| MA | Video | CPU (card cycle) | Driven by |
|:---|:---|:---|:---|
| MA0–MA6 | B0–B6 | A1–A7 | U1 |
| MA7–MA15 | L0–L8 | A8–A16 | U2 |
| MA16 | the page register | A17 | U2 |

A row is 128 bytes, of which 80 are on screen, so the address is the byte number written next to
the line number — plain concatenation, no adder and no multiply. Two pages of 480 × 128 = 61440
bytes fit in one AS6C1008 with room to spare.

MA7..MA15 carries only L0..L8. During lines 512..524 — deep in vertical blanking, where nothing is
fetched — the row field is therefore L mod 512. Nothing reads it.

The CPU addresses bytes only through `/LDS`, i.e. at odd addresses: byte n lives at `$A00001 + 2n`.
For a pixel that is `$A00001 + (page << 17) + (y << 8) + ((x >> 3) << 1)`, bit `7 - (x & 7)` — bit
7 is the leftmost pixel, the order the 166 shifts them out.

## 6. Bus Cycle

The card window is `$A00000–$BFFFFF`: `SEL = /EXPSEL · A23 · A21`. `/EXPSEL` is generated by the
SolderDemon m68k mainboard PLD (same as rosco_m68k r2) and already includes `/AS`. A22 needs no pin: `/EXPSEL` is only low for
`$100000-$DFFFFF`, and the only part of that with A23 and A21 both set is `$A00000-$BFFFFF`,
because `$E00000-$FFFFFF` is outside the expansion window. A20 splits the window: 0 = VRAM,
1 = register.

| U1 output | Equation | Drives |
|:---|:---|:---|
| `/SEL` | SEL | U2, and both halves of the multiplexer |
| `/SRAM_WE` | SEL·/A20·/RW·/LDS | SRAM WE# |
| `/BUF_OE` | BUFD·SEL·/A20·/LDS | /OE of the 74HCT245 |
| `/DTACK` | 0, OE = SEL·/LDS | bus `/DTACK` |
| `D0`, `D1` | VBLANK, HBLANK; OE = SEL·A20·RW·/LDS | status |

### SRAM OE# and BUFD

The SRAM's `OE#` is grounded — there is no pin to spare for it — so it drives MD whenever `WE#` is
high. That is safe as long as the 74HCT245 never drives MD while the SRAM still is:

- **Write.** `WE#` falls with `/LDS`, and the SRAM releases MD within tWHZ (≈ 20 ns) whatever OE#
  says — a write cycle always turns the outputs off. `BUFD` is a register clocked by CLK25, so
  `/BUF_OE` only asserts one clock (40.0 ns) after `/LDS` falls, which is longer. No overlap.
- **End of the cycle.** `/BUF_OE` also ANDs the live `/LDS`, so it deasserts immediately when
  `/LDS` rises, before the SRAM's outputs come back. Assert late, release early.
- **Read.** The SRAM is already driving; 40 ns of delay is nothing against the ~90 ns the read
  path takes anyway.

The simulation's contention check is what proves this: it watches every driver on MD0–MD7 and
reports any moment when two of them disagree.

### The control register, split across two chips

```
REGWR = SEL & A20 & !RW & !LDS_N;        /* the same term in both devices */
VIDEOON.D = (REGWR & D0.io) # (!REGWR & VIDEOON);     /* U1, bit 0 */
PAGE.D    = (REGWR & D1.io) # (!REGWR & PAGE);        /* U2, bit 1 */
```

U2 decodes the write from `SEL_N`, A20, R/W and `/LDS` — the same signals U1 uses — so the two
always agree about what a card cycle is, with no extra wire. Each bit is sampled on every 25 MHz
edge while the strobe is low, four or five chances per cycle, all well inside the window where the
CPU is holding data, so the 68010's data hold time does not matter.

`/RESET` reaches both devices on their GCLR input: black screen, page 0, after any reset.

The register is write-only. D0 and D1 are driven by U1 only during a status read; the rest of the
time its outputs are disabled, and the `.io` feedback in both chips reads the pin, which is how the
register write sees the data bus. D2..D7 are not driven — the driver masks them.

### Snow

While the CPU accesses the card, the multiplexer points at the CPU address for the whole cycle, so
the byte the 166 loads during that cycle is the wrong one: eight wrong pixels somewhere on the
current scanline. Draw on the hidden page and flip, or draw inside VBLANK.

A byte fetch needs the SRAM for only ~71 ns of each 320 ns byte time, so in principle the CPU could
have the rest and there would be no snow at all. That needs the read data to stay valid until the
68010 latches it, roughly 150 ns after `/DTACK` is recognised — an arbiter and a wait-state
generator. U1 has two spare macrocells and no spare pins.

## 7. Video Output

VGA wants 0.7 V across the monitor's 75 Ω termination, which is **9.3 mA per colour line** — about
26 mA from one driver for white. That is the number that decides this part of the circuit, and
nothing in a 5 V logic family is specified for it: a 74HC166 guarantees IOH = 4 mA and has a 20 mA
absolute maximum per pin, an ATF1502AS I/O even less. A 74AC166 *is* rated for 24 mA, but that
part is not a thing you can buy.

So `Q1` (2N3904, or any small-signal NPN) is an emitter follower:

```
U5 Qh ──[R6 220R]──┬── B     Q1      C ── +5 V
                   │        2N3904
                   └────────  E ──┬──[R1 390R]── VGA RED
                                  ├──[R2 390R]── VGA GREEN
                                  └──[R3 390R]── VGA BLUE
```

U5 supplies about 0.3 mA of base current; Q1 supplies the ~26 mA. The emitter sits at roughly
VOH − 0.7 V ≈ 4.1 V, so each line gets 4.1 × 75 / (390 + 75) ≈ **0.67 V** — 96 % of full scale.
When the pixel bit is 0 the transistor turns off and the monitor's own 75 Ω pulls the line to 0 V;
the emitter node's ~50 pF discharges through the load in under 10 ns, well inside a 40.0 ns pixel.

Because Q1 is a follower, the level per line is set by R1–R3 alone. Fitting only **R2** gives a
green screen and **R1 + R2** an amber one, both at the same brightness.

`/HSYNC` (U1) and `/VSYNC` (U2) go through 47 Ω (R4, R5) to J2 pins 13 and 14.

---

## 8. Power and Programming

Everything runs from the bus (+5 V, J1 pin 2); the card should take ~120–200 mA. Each CPLD has
four VCC/GND pairs and two bypass capacitors; the other ICs have one each, plus one at the
oscillator and C9 (47 µF) as bulk.

J3 is the standard Atmel 10-pin ISP header. The two devices are in one JTAG chain, TDI → U1 → U2
→ TDO, so one programmer run does both — but they take different `.jed` files, and swapping them
gives a board that looks alive and shows nothing.

## 10. If the fitter says no

Both fit today (U1 32/32 pins and 30/32 macrocells, U2 30/32 and 30/32, as the fitter counts them,
fold-back product terms included). If a change pushes one over, in rough order of what to try:

1. **Let the fitter move pins.** Change `PREASSIGN = KEEP` to `PREASSIGN = TRY` in the offending
   `.pld`, take the pinout it produces, put those pin numbers back into the `.pld`, and
   regenerate the board. Do not edit the schematic — it is generated from that file.
2. **Move work from U1 to U2.** U2 has two spare pins; its line-counter carries already use fold-back terms. The page register
   is already there; `/VSYNC` could be joined by almost anything that does not need many pins.
3. **Give up the HBLANK status bit.** D1 frees a pin and a macrocell on U1.
4. **Move to one bigger part.** An ATF1504AS in the 68-lead PLCC (64 macrocells, ~50 usable pins)
   does all of this in a single device — four ICs on the board, and one thing to program.
